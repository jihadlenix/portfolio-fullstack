The Mission

Half a feature is no feature. I take it to production.

A feature that works on a laptop is not finished. It needs an API that holds up, a database that does not buckle, access control that is actually enforced, and a deployment somebody can repeat. I build all of it, because the parts nobody wants to own are the parts that decide whether the thing survives contact with real users.

01 02 03

Pillar 01

Backend & APIs

The half of the product nobody sees and everybody depends on.

I build REST APIs and backend services in PHP and Symfony, Python and FastAPI, and C# and .NET. For the trading evaluation platform that meant a Symfony API behind challenge rules: configurable starting balances, profit targets and maximum-loss limits, with trade recording, profit and loss, win rate and equity all calculated server side. At Murex I integrated the ServiceNow API into PostgreSQL and built the services that filter assets by criteria and location, plus a role-based access control layer enforced in .NET middleware across every page and endpoint.

  • PHP / Symfony
  • Python / FastAPI
  • C# / .NET 9
  • Node.js / Express
  • Java / Spring Boot
  • REST APIs
  • RBAC

Pillar 02

Frontend, Data & Caching

Interfaces that stay fast once the data gets real.

React and Angular on the front, with the data layer built to match. The trading dashboard caches challenge and performance summaries in Redis and invalidates them when a trade changes, so the numbers stay both quick and correct, and the same Redis layer carries API rate limiting. At Murex the Angular UI recalculates a fiscal-year forecast the moment an asset manager changes a filter. On the news platform I built the Python collection pipeline, organised articles with Pandas, and wired FastAPI endpoints over MongoDB to the React filtering interface.

  • React
  • Angular
  • TypeScript
  • PostgreSQL
  • Redis
  • MongoDB
  • Pandas

Pillar 03

Taking It To Production

Running on real infrastructure, not on my laptop.

I took ITBF live on Murex virtual machines: Docker Compose, HTTPS and TLS with certificates coordinated through the Windows team, Microsoft SAML SSO, CI/CD and unit-tested calculation logic. The trading platform is containerised the same way. MediLog secures doctor access with JWT and Spring Security. Getting a certificate chain signed off by another team is not glamorous work, but it is the difference between a demo and something fifty people use on a Monday morning.

  • Docker Compose
  • CI/CD
  • HTTPS / TLS
  • SAML SSO
  • JWT
  • Unit testing
  • Linux
  • Git
